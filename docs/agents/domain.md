# Domain docs

## Before exploring

Read root `GLOSSARY.md` if present and relevant ADRs under `docs/adr/`.

If these documents do not exist, proceed silently. Domain modeling
creates them as terminology and decisions are resolved.

## Layout

Single-context: one root `GLOSSARY.md` and root `docs/adr/`.

## Vocabulary and decisions

Use glossary terms when naming domain concepts in issues, code,
tests, and proposals. Reconsider unfamiliar terms or note genuine
gaps for domain modeling.

Explicitly flag proposals that contradict an existing ADR, citing
the ADR and explaining why the decision should be reconsidered.
