# Image-only cave walls: bounded algorithm research

Research date: 2026-11-06. Recommendations below are engineering hypotheses, not measured cave-map accuracy. No model download, API inference, or benchmark experiment was performed. Target: new cave images with no inference-time reference geometry; reference DD2VTT may train/develop/evaluate. No source establishes 98% agreement with authored visibility geometry.

## What DD2VTT actually gives us

Official Dungeondraft docs expose an authored `Wall` with `Points`, `Loop`, and light occluders; `CaveMesh.Walls` is explicitly the collection automatically generated by that cave. Exporter separately exposes `ExportLOS`, `ExportObjectsLOS`, `ExportPortals`, and `ExportImageBase64`. This is strong evidence that Dungeondraft can export existing authoring geometry instead of recognizing walls from its rendered image. It is not proof of the exact production history of this particular CarlosProMaps file, nor inspection of proprietary exporter internals. [Wall API](https://megasploot.github.io/DungeondraftModdingAPI/reference/Wall/), [CaveMesh API](https://megasploot.github.io/DungeondraftModdingAPI/reference/CaveMesh/), [Exporter API](https://megasploot.github.io/DungeondraftModdingAPI/reference/Exporter/).

Implication (inference): image reconstruction is an inverse rendering/semantic segmentation problem. A rendered bevel, cliff face, shadow, texture stroke, or visible rock is not necessarily at the authored LOS position. Exact geometry may be underdetermined from pixels. A successful system must learn the intended blocking boundary convention as well as identify material.

## Ranked candidates

### 1. Multiscale material classifier + seeded graph optimization + contour tracing

Recommended first experiment. Learn class probabilities for solid rock/wall, traversable floor, water/other floor, and uncertain/decorative objects using color and local texture at several scales. A concrete primary-source reference implementation trains a random forest on labeled pixels using multiscale intensity and texture features; ilastik documents semantic probability maps, application to unseen images, and uncertainty-guided annotations. [scikit-image trainable segmentation](https://scikit-image.org/docs/stable/auto_examples/segmentation/plot_trainable_segmentation.html), [ilastik pixel classification](https://www.ilastik.org/documentation/pixelclassification/pixelclassification).

Proposed adaptation: turn reliable classifier probabilities into seeds; optimize a dense region labeling using unary class costs plus contrast-sensitive spatial agreement. Seed rock islands as well as the outer rock mass, and floor on both sides of narrow passages. Preserve entire solid regions and their holes. Only then trace the wall/floor interface. This combines reusable learned appearance with a deterministic geometry stage; it does not ask a vision agent to invent coordinate polylines.

A useful baseline is OpenCV GrabCut, which uses foreground/background Gaussian mixture appearance models and iterated graph cuts, accepting hard pixel labels. However, its normal rectangle initialization assumes foreground lies inside the rectangle; that is a poor fit for a cave's surrounding solid mass and many disconnected islands. Use mask initialization and compare against a custom multiclass or binary material graph model. [OpenCV GrabCut](https://docs.opencv.org/4.x/d8/d83/tutorial_py_grabcut.html).

Caveats (inferences): RGB-only GMMs may confuse similarly colored rock and floor. Strong smoothness can close a passage or remove a small rock island. One map supplies many correlated pixels, not many independent map styles. Hold out entire maps or at least complete spatial regions; random pixel train/test splits exaggerate generalization. Geometry offsets and ambiguous strips should not become confidently wrong material labels.

### 2. Small semantic seed/region annotation + the same deterministic solver

Recommended fallback if image-only automatic seeds fail. Have a human or one image-capable model label a bounded set of unmistakable floor/solid seed patches and ambiguous region IDs, using a numbered superpixel/crop overlay. Return labels/seed coordinates, not hundreds of freehand wall vertices. Dense graph optimization and contour extraction perform the precision work. This is an architecture proposal, not an existing accuracy claim.

Use an uncertainty map to request only missing semantic information. Enforce a fixed annotation/retry budget and explicitly report unresolved components. The ilastik workflow demonstrates uncertainty-guided labels; GrabCut and random walker demonstrate the usefulness of sparse fixed labels. [ilastik](https://www.ilastik.org/documentation/pixelclassification/pixelclassification), [GrabCut](https://docs.opencv.org/4.x/d8/d83/tutorial_py_grabcut.html), [random walker](https://scikit-image.org/docs/stable/auto_examples/segmentation/plot_random_walker_segmentation.html).

Cost using user-supplied SOL rates, not independently verified pricing: `2*uncached_input_M + .10*cached_input_M + 2.50*cache_write_M + 10*output_M` dollars. Example: 100k uncached billed input tokens plus 5k output tokens is $0.25; two such calls are $0.50. Image token accounting, retries, and cache writes must be included. No evidence here establishes how many image tokens or calls a map requires. Local deterministic processing incurs no paid model inference charge, but still uses machine time.

### 3. Prompted MobileSAM region proposals, then semantic selection and refinement

More realistic for CPU exploration than starting with a large generic SAM. Official MobileSAM code supports CPU, exposes positive/negative prompt prediction, and mentions ONNX export; the authors report roughly 3 seconds on their Mac i5. That is their demo measurement, not a full-resolution cave benchmark. The repository declares Apache-2.0. [MobileSAM source](https://github.com/ChaoningZhang/MobileSAM).

Proposed use: feed floor/rock seeds, test multiple masks, tile with overlap if necessary, then resolve labels and trace deterministically. A generic object mask is not inherently a rock-vs-floor classifier or a UVTT visibility model. It may select the cave as one object and overlook internal islands/cliffs; tiny passages may disappear under resize. Verify these specifically before investing in integration.

Original SAM's documented ONNX path exports its lightweight mask decoder; the image backbone is a separate stage. Do not assume an ONNX decoder alone provides end-to-end CPU segmentation. SAM2's official installation targets Linux/Python/PyTorch and includes optional CUDA postprocessing; its model/code checkpoints are Apache-2.0, with separately noted demo font licenses. Neither is a ready Rust-native cave solver. [SAM export documentation](https://github.com/facebookresearch/segment-anything#onnx-export), [SAM2 installation](https://github.com/facebookresearch/sam2/blob/main/INSTALL.md), [SAM2 licensing](https://github.com/facebookresearch/sam2#license).

## Classical methods worth comparing, not treating as semantic solutions

- **Random walker:** propagates multiple seed labels using similarity-weighted diffusion; good direct alternative when colors are noisy but boundaries remain coherent. Weak boundaries still permit leakage; large dense solves need memory/runtime measurement. [Official explanation](https://scikit-image.org/docs/stable/auto_examples/segmentation/plot_random_walker_segmentation.html).
- **Marker watershed:** floods a supplied elevation image from markers. Use smoothed learned boundary/material costs, not every texture minimum. It can cheaply partition ambiguous regions, but seed and elevation errors remain decisive. [Official watershed explanation](https://scikit-image.org/docs/stable/auto_examples/segmentation/plot_watershed.html).
- **Superpixels and region adjacency graphs:** reduce the optimization graph; classify and merge regions, then refine boundaries at full resolution. Superpixels crossing narrow passages create irreversible coarse errors unless refinement can split them. SLIC, flood fill, and related functions are documented in the [segmentation API](https://scikit-image.org/docs/stable/api/skimage.segmentation.html); graph operations in the [graph API](https://scikit-image.org/docs/stable/api/skimage.graph.html).
- **Region growing/flood fill:** excellent cheap baseline from high-confidence floor/rock seeds; local similarity thresholds alone can bridge weak boundaries and fragment textured interiors. Test it as a baseline rather than presuming it solves semantics.

## Ground truth, topology, and export contract

Proposed development protocol:

1. Parse reference vectors in the file's declared grid coordinate system, map to source-image pixels, and render a thin authoritative comparison mask. Audit whether paths close and whether they represent external boundaries, island boundaries, or open internal cliff lines.
2. Do not blindly fill every polygon: LOS segments do not automatically define a complete floor/solid semantic labeling. Closed contours can yield interior/exterior training masks after nesting classification; open walls need explicit side/material labels or remain boundary-only supervision. Exclude uncertain bands near reference boundaries when learning material appearance.
3. Evaluate semantic-region quality separately from boundary precision/recall at a declared pixel/grid tolerance. Define what “98%” means before reporting it. Require both precision and recall so extra walls cannot hide misses.
4. Add hard failure checks: reference/new output connected passage graph, preservation of rock islands and holes, sealed exits, segment self-intersections, and visibility disagreement from sampled floor viewpoints. A small geometric error across a corridor can be a large visibility error.
5. Extract nested contours from the final dense mask; preserve hierarchy and holes, simplify with a tolerance tied to grid scale, and reject simplification that changes connectivity. Open internal cliffs need a separate boundary class/representation; a two-class solid mask cannot encode every open blocking line. OpenCV supplies deterministic binary contour extraction and hierarchy. [Contours documentation](https://docs.opencv.org/4.x/d4/d73/tutorial_py_contours_begin.html).

CPU/Rust path (proposal): prototype classifier/solver choices with established CPU Python/C++ implementations, freeze intermediate probability/label/contour artifacts and runtime metrics, then implement the winning feature extraction/classifier/graph/trace stages in Rust or use a narrow native bridge. Avoid committing to crate choices before experiments establish the needed operations. Canny is useful as one boundary feature, but texture edges alone do not identify complete blocking regions or encode intended visibility.

## Decision

Start with candidate 1 and measured topology tests; add bounded semantic seed labeling only where confidence fails. Test MobileSAM as an optional proposer, not a replacement for semantic validation. A 98% goal on new maps remains unproven until evaluated on held-out map styles with explicit visibility/topology gates.
